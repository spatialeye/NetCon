# Release Notes
## Next release

The next release is planned for both NetCon 2026 (2026.1.2) and NetCon 2025 (2025.3.2). A change applies to both, unless stated otherwise.

Fixes:
* The meshed flow could depend on the order in which the connections were loaded. When a larger cycle shared its lower part with a smaller cycle that was found first, the connections above the shared part were marked as flowing down instead of meshed. Because NetCon 2025 and NetCon 2026 load the connections in a different order, they could compute a different flow for the same network. Every connection on a cycle is now marked meshed, whatever the load order. A network with a path that ends in several loops could also make the flow calculation run forever; this has been fixed as well.
* The worker settings of the [[../8 API/NetCon API Calls|NetCon API Calls]] (see [[../8 API/Rate limiting|Rate limiting]]) did not limit the number of traces that run at the same time. A trace left its worker as soon as it started streaming its result, so with 20 requests at once, 20 traces ran at once. A trace now keeps its worker until its result has been produced. Changes to `WorkerCount` and `MaxConcurrentSyncExecutions` now take effect without a restart.
* `Depth` and `SumCost` are now reserved field names in trace results, so a source column with one of these names no longer shows up as a NetCon value. Reserved names now ignore case: a source column such as `connectionid` no longer appears next to `ConnectionId`.
* Enriched asset data was only included in the results of the [[../8 API/NetCon API Calls|NetCon API Calls]] when the GeoJSON coordinate system setting was switched on. It is now always included. (NetCon 2025; NetCon 2026 has this since [[2.2 Version Information#Spatial Eye NetCon 2026.1.2.17|Spatial Eye NetCon 2026.1.2.17]].)
* The version that NetCon reports now includes the release number; before, the last part of the version was always 0. The network states call also returns the full (informational) version of the NetCon modules.

Enhancements:
* A data patch (see [[../5 Configuration/Configuration - 9. Overlay and Near Real Time Networks/Overlay - 1. Introduction to Overlay Networks|Overlay Networks]]) now only keeps its differences from the underlying network, for both the [[../5 Configuration/Indices|Indices]] and the flow, instead of a full copy. A data patch traces about as fast as its underlying network and uses much less memory. In a test with a large network and an empty data patch, the memory in use after loading went down from about 7.2 GB to about 5.3 GB. When a data patch cannot change the flow, the flow is not calculated again.
* The [[../5 Configuration/Indices|Indices]] use a more compact layout, which lowers the memory use and the time spent on garbage collection.
* Trace results are written to JSON about twice as fast, with the same output. In a test with a large trace (1.45 million results), writing went down from 37 to 53 seconds to about 19 seconds.
* A new parameter `Monitor Delta Connections` on the [[../5 Configuration/Configuration - 7. Sectioning and Tracing/NetConTrace feature source|NetConTrace feature source]], switched on by default. When it is switched off, NetCon still reads the delta tables while loading, but no longer checks them for changes. This is meant for analysing performance problems. A change of this parameter takes effect right away and does not reload the network.
* The log now shows the memory use and garbage collections of the process, to help analyse performance problems.
* The license check messages are clearer. (NetCon 2025)

## Spatial Eye NetCon 2026.1.2.17

Fixes:
* Errors of the [[../8 API/NetCon API Calls|NetCon API Calls]] were all answered with 500 (Internal Server Error). Now:
	* A full queue is answered with 429 (Too Many Requests, configurable with `OverloadHttpStatusCode`), and a request that does not finish in time, or arrives while the API is starting or stopping, with 503 (Service Unavailable). Both include a Retry-After header. See [[../8 API/Rate limiting|Rate limiting]].
	* The asynchronous calls answer an unknown or expired job ID with 404 (Not Found), and a request for the result of a job that is still running, has failed or was cancelled with 409 (Conflict). For a failed job, the response includes the error.
	* The error responses of every call are documented in Swagger.
* The result of an asynchronous query or trace could not be downloaded: the result URL in the job status did not work, and the download itself failed. Both work now, and the result looks the same as that of the synchronous call.
* Enriched asset data was only included in the results of the [[../8 API/NetCon API Calls|NetCon API Calls]] when the GeoJSON coordinate system setting was switched on. It is now always included.
* A source column with the same name as a field that NetCon writes itself, such as `Label`, `Role` or `IsBarrier`, could show up as the NetCon value when NetCon had no value for that connection. These names are now reserved and such source columns are left out.

Enhancements:
* The [[../6 Use/NetCon Portal/NetCon Portal - 1. Introduction|NetCon Portal]] can now be translated. English is the default, and Japanese has been added.
* A template project and instructions to create a viewer project for the NetCon Portal have been added. See [[../5 Configuration/Configuration - 10. NetCon Portal/NetCon Portal - 1. Viewer Project configuration|NetCon Portal - 1. Viewer Project configuration]].
* The database scripts of the NetCon Portal no longer require a specific database user, and include instructions for each database system.

## Spatial Eye NetCon 2026.1.2.16

Fixes:
* Many fixes to the engines that load and keep the networks up to date, for setups with several networks, data patches and [[../5 Configuration/Configuration - 9. Overlay and Near Real Time Networks/Overlay - 1. Introduction to Overlay Networks|Overlay Networks]]. For example:
	* A warehouse load waits until the overlay networks it depends on are loaded.
	* Queries on the server wait for a reload that is in progress, and fail with a clear message when a load has failed.
	* An engine that keeps failing is restarted a limited number of times, instead of over and over again.
	* A change made in Spatial Workshop no longer interrupts a load that is in progress.
	* NetCon starts loading the networks once the project has loaded.
* The [[../8 API/NetCon API Calls|NetCon API Calls]] answer a request for an unknown network with 404 (Not Found).
* NetCon writes less to the log, and log lines of an engine or task start with its name.

Enhancements:
* The [[../6 Use/NetCon Portal/NetCon Portal - 1. Introduction|NetCon Portal]] has been reworked:
	* Trace results are shown as connection records, which can be exported. The **Get Assets** button retrieves the assets themselves.
	* **Barrier State Change** offers every state that can be set (for example Open, Closed, Throttled, Auto Open, Always Closed). The Task ID is optional.
	* **Outage analysis** returns only the affected service points and the valves to close.
	* The data quality form has been replaced by a data patch form. The Outage Info form has been removed, because it no longer worked with the current data model.
	* Errors are reported with a reason, for example an unknown state or a network that is not ready yet.
	* Several users can work at the same time, each with their own form state.

Enhancements:
* The [[../6 Use/NetCon Portal/NetCon Portal - 1. Introduction|NetCon Portal]] finds the connection of an asset by its asset table name and asset id. Table names that differ between the asset and the network can be mapped in the configuration.

## Spatial Eye NetCon 2025.3.2.5

Fixes: 
* [[../8 API/Rate limiting|Rate limiting]] has been enabled to optimize the throughput of [[../8 API/NetCon API Calls|NetCon API Calls]]. Please set the defaults to match the number of virtual processors in the server.
* When the [[../8 API/NetCon API Calls|NetCon API Calls]] were under heavy load the geometry cache could incidentally lock, and could become large. It now has a concurrent implementation, and its purging has been made much faster. Also, it possible to preload all geometries by setting the [[../../Geometry Retention Time|Geometry Retention Time]] to 0 (minutes).
	* For each new [[../5 Configuration/Configuration - 7. Sectioning and Tracing/NetConTrace feature source|NetConTrace feature source]] the parameter is added.

```xml

      <Name>geom_retention_minutes</Name>
      <ExternalName>Geometry Retention Minutes</ExternalName>
      <FieldType>Int</FieldType>
      <Value Type="User">
       <Value>0</Value>
      </Value>
      <LookupValuesOnly>false</LookupValuesOnly>
      <AllowCacheParameterDependentCollection>true</AllowCacheParameterDependentCollection>
     </Parameter>
```
